## T1-8. Защита от подмены данных
Проверяем, что нельзя использовать один и тот же ключ подтверждения для разных платежей.
Входные данные (запрос 1):
{
  "order_id": "ord_idem_A",
  "recipient": "clinic_medservice",
  "purpose": "первый платеж",
  "amount": 1000.0,
  "currency": "RUB"
}

**Ожидание:** CREATED.
Входные данные (запрос 2 — тот же ключ, другое тело):
{
  "order_id": "ord_idem_B",
  "recipient": "clinic_pharmacy",
  "purpose": "совсем другой платеж",
  "amount": 99999.0,
  "currency": "RUB"
}
Ожидание: IDEMPOTENCY_KEY_REUSED, потому что same_request сравнивает amount, order_id, recipient, purpose, currency и видит расхождение.


**Факт:**
{
  "error_code": "IDEMPOTENCY_KEY_REUSED",
  "message": "Idempotency-Key уже использован с другим телом запроса",
  "retryable": false
}
**Пройден:** [+] да [ ] нет
