# Платёжный сервис Med-Service (CLI-прототип)

Это консольный прототип (CLI) платёжного сервиса для клиники. Прототип эмулирует работу банковского шлюза, поддерживает двухэтапную оплату (создание + подтверждение), строгую валидацию, защиту от брутфорса и ведение аудита.

## ⚙️ Требования
- Установленный Python 3.8 или выше.
- Дополнительные библиотеки не требуются (используется только стандартная библиотека Python).

## 📁 Структура проекта
- `05_app.py` — основной файл приложения (точка входа).
- `gateway_emulator.py` — модуль эмуляции банковского шлюза.
- `payment.json` — пример входящего запроса на оплату.
- `01_данные/recipients.csv` — справочник активных получателей.
- `payments_out.csv` — база данных (журнал платежей). Создается автоматически.
- `events.log` — журнал аудита (история смены статусов). Создается автоматически.
- `tokens.json` — имитация кэша для хранения токенов подтверждения (TTL). Создается автоматически.

## 🚀 Как запускать

Скрипт поддерживает 4 команды: `create`, `confirm`, `status` и `cancel`.
*(Примечание: так как проект консольный, `Idempotency-Key`, который в реальном API передается в заголовках, мы передаем третьим аргументом командной строки).*

### 1. Создание платежа (create)
Создает платеж в статусе `CREATED`, генерирует токен подтверждения и сохраняет его в кэш.
**Команда:**
`python 05_app.py create payment.json idem_001`

### 2. Подтверждение платежа (confirm)
Проверяет токен, защищает от перебора (брутфорса) и отправляет запрос в банк.
**Команда:**
`python 05_app.py confirm <payment_id> <confirm_token>`
*Пример:* `python 05_app.py confirm pay_demo_1001 a1b2c3`

### 3. Проверка статуса (status)
Возвращает текущий статус платежа и историю его изменений (audit log).
**Команда:**
`python 05_app.py status <payment_id>`

### 4. Отмена платежа (cancel)
Отменяет платеж, если он еще не был успешно оплачен (находится в статусе `CREATED` или `PENDING`).
**Команда:**
`python 05_app.py cancel <payment_id>`

## 🧪 Тестирование различных сценариев шлюза

Эмулятор выбирает результат в зависимости от хэша `order_id`. Чтобы проверить разные сценарии, просто меняйте `order_id` в файле `payment.json`:

- 🟢 Успех (SUCCESS): `"order_id": "ord_1001"`
- 🔴 Недостаточно средств (INSUFFICIENT_FUNDS): `"order_id": "ord_1007"`
- 🔴 Карта отклонена (CARD_DECLINED): `"order_id": "ord_1008"`
- 🟡 Таймаут (TIMEOUT -> PENDING): `"order_id": "ord_1009"`
